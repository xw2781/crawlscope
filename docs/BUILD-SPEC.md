# crawlscope — product spec (internal, for the coding agent)

Open-source (MIT), free, unlimited-URL, local SEO site crawler with a native agent interface (MCP + JSON) and modern GEO/AEO checks.
CLEAN-ROOM: do not copy Screaming Frog's UI, wording, tab names, or assets. Use only public SEO knowledge (Google Search Central docs, RFC 9309 robots, sitemaps.org, schema.org, llmstxt.org). Original naming of issues and own design.

## Stack
Node >= 20 (we run 24), TypeScript (ESM), build with tsup or tsc. Runtime deps kept small: cheerio (HTML parse), commander or cac (CLI), @modelcontextprotocol/sdk + zod (MCP), undici or built-in fetch. Dev: vitest, typescript. No heavy frameworks for the UI: web UI is a single self-contained vanilla JS/CSS page served by a node http server (no build step needed for it).
Package name `crawlscope`, bin `crawlscope`. `npx crawlscope crawl https://example.com` must work after `npm publish` (we are NOT publishing now; make `npm pack` + `npm i -g ./tarball` work and test it).

## CLI
- `crawlscope crawl <url> [--out dir] [--max-pages N (default unlimited)] [--max-depth N] [--concurrency N (default 4)] [--delay ms (default 250 per host)] [--include regex ...] [--exclude regex ...] [--user-agent s] [--no-robots (requires --i-own-this-site)] [--respect-nofollow] [--timeout ms] [--sitemap url] [--json] [--format html,json,csv] [--resume] [--ai-bots-check]`
  Writes a crawl directory: `crawl.json` (full result), `pages.csv`, `issues.csv`, `links.csv`, `report.html`, plus a sqlite-free incremental store (`state.jsonl`) so `--resume`/incremental re-crawl works: on re-crawl send If-None-Match/If-Modified-Since using stored ETag/Last-Modified and reuse unchanged page data.
  Prints a clear colored CLI summary (counts by severity, top issues, slowest pages, status code table). `--json` prints machine-readable summary JSON to stdout only (no other stdout noise; logs to stderr). Exit code option `--fail-on error|warning` for CI.
- `crawlscope report <crawl-dir> [--open]` regenerate HTML/CSV from crawl.json.
- `crawlscope diff <crawlA> <crawlB> [--json] [--html out.html]` crawl-to-crawl diff: new/removed pages, status changes, title/meta/h1/canonical changes, issues added/resolved/persisting, response-time & size deltas, link-count changes.
- `crawlscope ui [dir] [--port 4173]` local web UI (127.0.0.1 only): start a crawl from the browser with live progress (SSE), browse pages table with filtering/sorting/search, issues view grouped by check with severity, page detail (headers, links in/out, structured data, redirect chain), compare two crawls, export. Prior crawls listed from a workspace dir (default ./crawlscope-data or ~/.crawlscope).
- `crawlscope mcp` MCP server over stdio.
- `crawlscope llms <url>` / `crawlscope ai-readiness <url>`: quick GEO/AEO check for a single site (llms.txt, robots AI bot rules, structured data, etc.).

## Politeness (must)
Obey robots.txt (RFC 9309: longest-match Allow/Disallow, wildcards * and $, UA group selection, Crawl-delay honored as per-host delay minimum). Default UA `crawlscope/<version> (+https://github.com/xw2781/crawlscope)`. Per-host delay, concurrency cap, retry with backoff on 429/503 respecting Retry-After, request timeout, max response size cap for body parse (e.g. 5MB), content-type gating. Stay on same registrable site by default (configurable `--subdomains`, `--external-check` HEAD-checks outbound links but never crawls them).

## Checks (each with id, severity error/warning/notice, description, how-to-fix text; original wording)
Response & links: status 4xx/5xx pages, broken internal links, broken external links (HEAD then GET fallback), redirect (301/302/307/308), redirect chains & loops, redirect to different host, mixed content http resources on https, slow response (>1s warn, >3s error, configurable), large HTML (>1MB?), non-200 sitemap URLs, timeouts/DNS errors.
On-page: title missing/empty/duplicate/too long (>60 chars or ~580px approx)/too short(<30), meta description missing/duplicate/too long(>160)/short(<70), H1 missing/multiple/duplicate/empty, heading order skips, canonical missing / multiple / non-self / canonicalised-to-other / canonical to non-200 / canonical relative-vs-absolute, meta robots & X-Robots-Tag noindex/nofollow, noindex page in sitemap, indexable page blocked by robots, hreflang (invalid codes, missing self-reference, missing return links, hreflang to non-200/noindex, x-default), images missing alt (and empty alt notice), image dimensions missing (CLS notice), viewport meta missing, html lang missing, thin content (word count < 200 notice), duplicate content via content hash (exact) and simhash near-duplicates, URL hygiene (uppercase, underscores, params, >115 chars, spaces), pagination rel next/prev notice, Open Graph/Twitter card missing basics.
Site-level: sitemap discovery (robots Sitemap:, /sitemap.xml, sitemap index, gz), sitemap vs crawled comparison (in sitemap not crawled/not linked = orphan; crawled indexable but not in sitemap), internal inlinks/outlinks counts, orphan pages (in sitemap but zero inlinks), crawl depth, pages with too few inlinks, link text empty/generic ("click here"), nofollow internal links, robots.txt present/valid & syntax warnings, security basics (HTTPS, HSTS, redirect http->https), favicon, 404 page returns real 404 (soft-404 probe).
Structured data: extract JSON-LD, Microdata, RDFa(basic); validate JSON-LD parses, has @context/@type, required properties for common types (Organization, WebSite, Article/BlogPosting/NewsArticle, Product, BreadcrumbList, FAQPage, LocalBusiness, Person, Event, Recipe, VideoObject) per Google docs (own table), flag invalid JSON, missing required/recommended props, mismatch notes.
GEO/AEO (separate "AI readiness" category + score 0-100 with breakdown): /llms.txt and /llms-full.txt presence and format validity per llmstxt.org (H1, blockquote summary, H2 sections with links list, links resolve), robots.txt rules per AI crawler (GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-User, Claude-SearchBot, anthropic-ai, PerplexityBot, Perplexity-User, Google-Extended, Applebot-Extended, CCBot, Bytespider, Amazonbot, Meta-ExternalAgent, cohere-ai, DuckAssistBot, etc.) reporting allowed/blocked per bot and a note distinguishing training vs search/retrieval bots, JSON-LD coverage (Organization/WebSite/Article/FAQ/author/dates), clear authorship & dates, semantic HTML (main/article/headings), FAQ/Q&A-structured content, content extractable without JS (flag pages with almost empty body/heavy JS-only shells), meta robots snippet controls (nosnippet, max-snippet, noai/noimageai notices), sitemap lastmod present, canonical consistency, page text-to-HTML ratio, schema `sameAs` links, TLDR/summary presence heuristics (keep honest: label heuristics as heuristics). Keep the data in an `aiReadiness` object in crawl.json.

## Outputs
- `crawl.json` stable, versioned schema (`schemaVersion`), documented in docs/schema.md.
- CSV exports (pages, issues, links).
- `report.html`: BEAUTIFUL, fully self-contained single file (inline CSS/JS/data, no external requests, works offline, light+dark theme, responsive, print-friendly). Sections: overview dashboard with health score, severity donut/bars, status-code distribution chart, crawl-depth chart, response-time histogram, AI-readiness card with per-bot allow/block grid, top issues list with expandable affected URLs and how-to-fix, searchable/sortable/filterable pages table, link graph summary (top inlinked/orphans), sitemap comparison, structured data summary, diff section when generated by `diff`. Charts via inline SVG written by hand (no CDN). Original, modern design (pick a distinct visual identity, not resembling the competitor).
- Diff HTML report too.

## MCP server tools (stdio, `crawlscope mcp`)
`crawl_site` (url + options; runs crawl, returns crawl id + compact summary; supports max_pages cap default 200 for agents), `get_crawl_summary`, `list_crawls`, `list_issues` (filters: severity, check id, limit), `get_page` (url -> full page record incl. issues, links, structured data), `find_pages` (filter by status/title/etc.), `audit_url` (single-URL audit without full crawl), `check_ai_readiness` (site), `check_robots_url` (is URL allowed for UA), `diff_crawls`, `export_report` (path to html/csv).
